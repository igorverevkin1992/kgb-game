# Как править игровой контент

Весь контент игры лежит в `content/` в виде JSON-файлов. Код трогать не нужно:
поправь текст или число, запусти проверку, и валидатор скажет, если что-то сломалось.

```bash
tools/validate.sh
```

Проверку запускает и CI на GitHub при каждом пуше, так что ошибку вы увидите и без запуска
у себя. В редакторе Godot контент проверяется при старте игры: с ошибкой игра не запустится и
покажет сообщение.

## Где что лежит

| Папка / файл | Что внутри | Формат |
|---|---|---|
| `campaign.json` | Акты: название, недели, дата начала, цель акта (кого нужно завербовать) | один объект |
| `balance.json` | Числа баланса: стартовые риски и спецфонд, на сколько растут шкалы, пороги | один объект |
| `targets/*.json` | Цели пирамиды вербовки: должность, матрица MICE, подход, как открывается | один файл — одна цель |
| `clues/*.json` | Улики для доски MICE: откуда берутся и что вскрывают | массив улик |
| `cables/*.json` | Утренняя почта: депеши Центра, вырезки, справки, перехваты | массив |
| `ops/*.json` | Полевые операции: цель на карте, есть ли хвост и его примета, последствия | один файл — одна операция |
| `map/sites.json` | Карта: районы и точки (бытовые остановки, цели, ориентиры) с координатами в милях | один объект |
| `map/cues.json` | Приметы для карточек наблюдения на маршруте SDR | массив |
| `polygraph/*.json` | Экзамены на полиграфе ЦРУ: экзаменатор, вопросы, варианты ответов | один файл — один экзамен |
| `dialogs/*.json` | Вербовочные беседы: реплики собеседника, ответы по тонам, козыри из досье | один файл — одна беседа |
| `achievements/*.json` | Достижения Steam: id, название, описание и событие, которое их открывает | массив |
| `archive/*.json` | «Архив 1985»: справочные записи (история, техника, законы, факт и вымысел) | массив |
| `requests/*.json` | Запросы в Центр для ночной шифрограммы: деньги, продление срока и т. п. | массив |

## Тексты

Каждый текст пишется на двух языках:

```json
"title": { "ru": "Неотправленная записка", "en": "The unsent memo" }
```

Сейчас делаем только русскую версию: `en` можно не заполнять. Весь русский текст — без латиницы:
бренды пишем транслитом в кавычках («Ферст Вирджиния бэнк», «Форд ЛТД»), аббревиатуры — по-русски
(«проверочный маршрут», «наружка ФБР», «отчёт о валютной операции (форма 4789)»), суммы — словами
(«10 000 долларов»). Тест `tools/test.sh` не пропустит латиницу в русских текстах. Когда дойдём до
английской версии, `tools/validate.sh --en` покажет, что ещё не переведено.
Документы и улики — **не длиннее 150 слов** (лучше до 120). Это защита от «стены текста».

## Как устроены улики

У каждой улики есть **источник** — один из трёх путей:

- `"channel": "document", "from": "cable_..."` — пришла с утренней почтой;
- `"channel": "field", "from": "op_..."` — найдена в полевой операции на карте;
- `"channel": "agent", "from": "tar_..."` — сообщил завербованный агент;
- `"channel": "meeting", "from": "dlg_..."` — оговорка собеседника на встрече: фраза `chunk`
  должна дословно встречаться в его репликах в этой беседе; игрок снимает её с катушки.

Поле `reveals` говорит, какую ось MICE у какой цели вскрывает улика:

```json
"reveals": [{ "target_id": "tar_vargas_ellen", "axis": "money" }]
```

## Правила, которые проверяет валидатор

1. **«Правило трёх улик».** К каждой цели ведут улики минимум из 3 независимых источников.
   Если любой один источник сорвётся, оставшихся улик всё равно хватит. Каждую ведущую ось MICE
   (`approach.key_axes`) вскрывают минимум 3 улики.
2. **Нет софтлоков.** Цель каждого акта достижима, даже если провалится вербовка любой одной
   цели или сорвётся любая одна операция.
3. **Честный SDR.** Местные приметы (`ambient_tags`) у разных точек не совпадают, иначе на
   маршруте через обе точки игрок увидит ложный повтор. Примета хвоста операции — вида `tail`.
   Есть хотя бы три района с бытовыми точками внутри 25-мильной зоны — правильный маршрут возможен.
4. **Ссылки целы.** Все `cable_...`, `op_...`, `tar_...`, `clue_...` существуют, id не повторяются.
5. **Недели** депеш и операций попадают в рамки своего акта из `campaign.json`.

Ошибка (красная) ломает сборку, её нужно исправить. Предупреждение (жёлтое) — подсказка.

## Карта и маршрут SDR (`map/`)

Маршрут прокладывает сам игрок: три бытовые точки (`role: "stop"`), затем цель операции
(`role: "target"`). Карточки наблюдений на каждой точке собирает движок:

- одна **местная примета** точки — из её `ambient_tags` («Почтальон с тележкой»);
- один **случайный прохожий** — из примет вида `noise` («Женщина в красном шарфе»), без повторов;
- можно добавлять «почти двойников» хвоста среди `noise` («Тёмно-синий седан Ford LTD» рядом
  со «Светло-синим») — это тест внимательности; одинаковых текстов у разных примет быть не должно;
- если за резидентом **хвост** — примета вида `tail` («Светло-синий седан Ford LTD»). Когда все три
  точки в разных районах, она мелькает на двух точках («дважды — работа противника»); если
  районов меньше — только на одной, и хвост легко пропустить.

Точка описывается так:

```json
{
  "site_id": "site_safeway_clarendon",
  "name": { "ru": "Safeway, Кларендон", "en": "Safeway, Clarendon" },
  "kind": "grocery",
  "role": "stop",
  "district": "arlington",
  "pos": { "x": 31.0, "y": 19.9 },
  "cover_reason": { "ru": "Купить продукты на неделю", "en": "Groceries for the week" },
  "ambient_tags": ["mother_stroller", "teen_shopping_carts"]
}
```

`pos` — мили от левого верхнего угла карты (посольство на Маунт-Алто — x 32, y 16; 1 миля к
востоку — x+1, к югу — y+1). Радиус дипломатической зоны и посольство задаются в
`balance.json → sdr`. Точки дальше 25 миль игрок выбрать может, но наружка это заметит.

## Доска мотивов: фрагменты в документах и заключение по досье

**Фрагмент-улика.** У улики из документа (`"channel": "document"`) есть поле `chunk` — фраза,
которая подсвечивается в тексте документа; игрок щёлкает по ней и снимает улику на доску:

```json
"chunk": "недостача 340 долларов в кассе № 2"
```

Фраза должна дословно встречаться в тексте документа (`body.ru`) — иначе валидатор скажет,
что фрагмента нет. Удобно копировать её прямо из текста депеши.

**Заключение по досье.** У каждой цели есть блок `analysis` — правильный ответ для формы
«Заключение» (проверка сразу по трём пунктам):

```json
"analysis": {
  "leading_axis": "money",
  "access_options": [
    { "id": "cia_staff_accounts", "text": { "ru": "Ипотечные и зарплатные счета сотрудников ЦРУ" } },
    { "id": "branch_vault", "text": { "ru": "Хранилище и инкассация отделения" } }
  ],
  "correct_access": "cia_staff_accounts",
  "hint": { "ru": "Что Варгас нужнее всего прямо сейчас — и что она прячет от управляющего?" }
}
```

- `leading_axis` — ведущий мотив: `money` (Деньги), `ideology` (Идеология), `compromise`
  (Компромат), `ego` (Самолюбие); должен быть среди `approach.key_axes`.
- `access_options` — варианты «Доступа»: один правильный (`correct_access`) и правдоподобные
  ложные (продуктивные ложные следы).
- Третий пункт — канал подхода — сверяется с `approach.flag_mode`.
- `hint` — первая подсказка (намёк). Вторая (какую улику перечитать) и третья (ответ про мотив)
  строятся автоматически.

Мотив на доске «подтверждён», когда к его ячейке приколоты три улики: тогда игрок видит
истинную цифру `mice_profile.<мотив>.true_value`, а если `backfire_risk` ≥ 0.5 — пометку
«красная линия» (давить на этот мотив опасно).

## Шифроузел «Фиалка»: директивы и запросы в Центр

**Директивы.** Депеши с `"kind": "directive"` приходят не в лоток, а на «Фиалку»: игрок
выставляет ключ, принимает шифрограмму и сверяет контрольную группу с ключевым блокнотом.
Ключ и группа на каждую неделю вычисляются сами — писать их не нужно. Чтобы сделать директиву
**подложной** (провокация ФБР), добавьте поле:

```json
"forged": true
```

Тогда цифры её контрольной группы будут переставлены, и внимательный игрок это заметит. Хорошо,
если и сам текст чем-то настораживает (просьба не проходить проверочный маршрут, «подтверждения
не требуется»). Подложной может быть только директива — валидатор проверит.

**Запросы в Центр** (`requests/*.json`) игрок может приложить к ночной шифрограмме, каждый — один
раз в своём акте:

```json
{
  "request_id": "req_a1_fund",
  "act": 1,
  "title": { "ru": "Пополнить спецфонд на 10 000 долларов" },
  "phrase": { "ru": "Прошу выделить дополнительно 10 000 долларов на оперативные расходы." },
  "min_trust": 55,
  "granted": { "fund_usd": 10000, "moscow_pressure": 4 },
  "refused": { "centre_trust": -3 }
}
```

- `title` — надпись на кнопке, `phrase` — фраза в тексте шифрограммы;
- `min_trust` — с какого Доверия Центра запрос одобрят (игрок видит порог и текущее доверие);
- `granted` — что будет при одобрении: `fund_usd` (деньги в спецфонд), `centre_trust`,
  `moscow_pressure`, `extend_act_weeks` (на сколько недель продлить срок задачи акта);
- `refused` — что будет при отказе: `centre_trust`, `moscow_pressure`.

## Финансы агента и задача акта

У цели может быть блок `finance` — что резидент обещал на встрече и сколько цель зарабатывает:

```json
"finance": {
  "salary_usd": 24000,
  "promised_usd": 11400,
  "promise": { "ru": "Погасить долг клинике в Бетесде за лечение матери" }
}
```

- `promised_usd` — обещанный первый транш. Пока он не выплачен и не отправлен, лояльность
  агента каждую неделю падает. Больше 10 000 долларов одним вкладом — банк подаст форму 4789.
- `salary_usd` — годовая зарплата: чем она меньше, тем заметнее наличные в образе жизни.

В `campaign.json` у цели акта можно поставить `"settle_promise": true` — тогда задача акта
выполнена, только когда завербованному агенту выплачено обещанное (валидатор проверит, что
обещание помещается в стартовый спецфонд).

## Вербовочные беседы (`dialogs/`)

Беседа — несколько реплик собеседника (`beats`). На каждую игрок отвечает одним из четырёх
тонов: `empathy` (эмпатия), `pragmatic` (деловой прагматизм), `pressure` (мягкое давление),
`ego` (апелляция к эго). К тону можно добавить **козырь** — улику, приколотую к досье.

```json
{
  "dialog_id": "dlg_a1_vargas",
  "target_id": "tar_vargas_ellen",
  "title": { "ru": "Кафе у станции «Кларендон»" },
  "setting": { "ru": "Вторник, половина седьмого. …" },
  "offer_rapport": 60,
  "offer": { "line": { "ru": "Предложение резидента" }, "reply": { "ru": "Согласие" } },
  "beats": [
    {
      "prompt": { "ru": "Что говорит собеседник" },
      "tones": {
        "empathy":   { "line": { "ru": "Ответ резидента" }, "rapport": 14, "anxiety": 5, "reply": { "ru": "Реакция" } },
        "pragmatic": { "line": …, "rapport": 10, "anxiety": -5, "reply": … },
        "pressure":  { … },
        "ego":       { … }
      }
    }
  ],
  "trumps": [
    {
      "clue_id": "clue_vargas_clinic_debt",
      "line": { "ru": "Что говорит резидент, выкладывая козырь" },
      "min_rapport": 25,
      "ready": { "rapport": 22, "anxiety": -5, "reply": { "ru": "Реакция, если Раппорт уже от 25" } },
      "early": { "rapport": 0, "anxiety": 25, "reply": { "ru": "Реакция, если рано" } }
    }
  ]
}
```

- Стартовые Раппорт и Тревога берутся из досье цели (`initial_state.rapport`, `paranoia`).
- `rapport` и `anxiety` у тона и козыря — на сколько изменится индикатор (минус — падает).
- `offer_rapport` — с какого Раппорта можно сделать предложение; `max_anxiety` (по умолчанию
  100) — при какой Тревоге собеседник уходит, и подход проваливается.
- Козырь срабатывает (`ready`), если Раппорт уже не ниже `min_rapport`, иначе — `early`
  (обычно всплеск Тревоги: шантаж на старте). Козырем может быть только улика по этой цели.
- Валидатор проверяет, что беседу **можно выиграть** идеальной игрой, и предупреждает, если её
  можно выиграть вообще без козырей (тогда доска мотивов на встрече не нужна).
- Без беседы цель нельзя завербовать — валидатор найдёт тупик, если это цель акта.

## Встречи на связи с агентами (`dialogs/`, `kind: "handling"`)

После вербовки с агентом можно встречаться ещё — вторая, третья встреча. Формат тот же, что у
вербовочной беседы (реплики по тонам, `offer` — договорённость), плюс поля:
- `kind: "handling"`, `order` — номер встречи у этого агента (идут по порядку);
- `requires` — `act` (не раньше фазы), `flags`, `polygraph: true` (когда «Кроноса» вызвали на проверку);
- `start_anxiety` — настороженность в начале; контакт в начале — лояльность агента;
- `success` — что даст договорённость: `text`, `loyalty`, `lifestyle`, `sog_heat`, `mole_hunt`,
  `centre_trust`, `clue_ids` (только донесения этого агента — придут сразу), `flag_set`,
  `polygraph_slots` (пункты подготовки к полиграфу);
- `failure` — если сорвалась: `text`, `loyalty`. Агент при этом не теряется.
Личная встреча всегда немного греет наружку: `balance.json → meeting.handling_sog_heat`.
Валидатор проверяет, что встречу можно выиграть при лояльности агента 50 %, что номера не
повторяются и что с бесконтактным агентом (Хэйлс) встреч нет.

## Сюжетные линии и развилки

- **Документ по условию** — `requires_flags: ["флаг"]` у документа: он придёт утром после того,
  как флаг поставлен (вариантом решения, исходом разговора, выходом). Так ветки решений получают
  свои письма, сводки и справки.
- **Разговор** — беседа `kind: "conversation"`: собеседник не кандидат (`person` — имя), есть
  `requires` (`act`, `week`, `flags`), `start_rapport` и `start_anxiety`, итоги `success` /
  `failure` с `flag_set`, рисками, Доверием Центра. Разговор появляется на магнитофоне, когда
  условия выполнены, и проходит один раз.
- **Варианты фазы** — у фазы `variants`: первый вариант, у которого есть все `flags_all`,
  заменяет `title`, `intro`, `outro`. Пятая фаза так становится «Римом», «Повторной проверкой»,
  «Эвакуацией» или «Пустым каналом».
- **Встречи на связи-варианты** — несколько встреч одного агента с одинаковым `order`, но разными
  `requires.flags`: откроется та, чьи флаги поставлены.
- **Хроника судеб в эпилоге** — запись архива в разделе `epilogue` с условием из нескольких частей
  через «+»: `"unlock": "ending:campaign_complete+flag:kronos_farewell"` — лист откроется в финале,
  если поставлен флаг. Части: событие движка, `ending:<концовка>`, `flag:<флаг>`.
- **Флаги исходов**: `polygraph_passed`, `polygraph_inconclusive`, `polygraph_failed`,
  `kronos_absent` («Кронос» потерян до проверки), `contact_<id цели>` — связь через тайник установлена,
  `recruited_<id цели>` — кандидат завербован (документы, решения и разговоры линии агента).
- **Флаг успеха выхода** — `"success_flag": "illegal_supplied"` в операции: флаг ставится, если
  выход прошёл чисто (без срыва и без хвоста). По нему открываются документы и решения линии.

## Вторая фаза: фазы операции, тайники, поручения, решения

**Фаза операции** в `campaign.json` может иметь `intro` (вводная при начале фазы) и `outro` (итог) —
они показываются на карточке смены фаз.

**Донесения агентов по фазам.** У сведений с `"channel": "agent"` можно указать `"act": 2` —
агент сообщит их только со второй фазы. Агент приносит по одному донесению в неделю, по порядку
файлов, пропуская уже полученные.

**Тайник для бесконтактного агента** — выход (`ops/`) с полями:

```json
"contact_target_id": "tar_hales_robert",
"requires_targets_unlocked": ["tar_hales_robert"],
"drop": { "codename": "ЭЛЛИС", "signal": { "ru": "Метка мелом на табличке" }, "container": { "ru": "Полый штырь под мостиком" } }
```

Выход доступен после утверждённого заключения; чистый проход (без хвоста) устанавливает связь —
кандидат завербован. Беседа такому кандидату не нужна (в `approach.flag_mode` — `contactless`).

**Что даёт агент** — поле цели `perks`: `["sog_schedule"]` — после вербовки на карте у каждого
выхода видно, будет ли наружка.

**Оперработники** (`operatives/*.json`): `operative_id`, `name`, `bio`, `notice_chance` — с какой
вероятностью он заметит наружку (на маршруте в одном-двух районах — меньше на
`balance.delegation.few_districts_penalty`). Поручать выходы можно после
`balance.delegation.unlock_after_personal_ops` личных выходов.

**Приёмы наружки** — у выхода `sdr.technique`: `relay` (эстафета машин — повторяется человек, а не
машина), `clothes` (смена одежды — у приметы есть `variants`, разные описания на разных точках),
`aircraft` (самолёт). Приём можно использовать только после депеши с `"teaches": "<приём>"`,
пришедшей раньше этой недели, — валидатор проверит. Ставьте ориентировки на тихие недели.

**Решения резидента** (`decisions/*.json`): `decision_id`, `act`, `trigger` (`week`, `clue_id`,
`flag` — когда появится), `sender`, `title`, `text` и `options` — у каждого `label`, `outcome` и
`effects`: шкалы рисков, `centre_trust`, `fund_usd`, `flag_set`, `operative_out` (вывести
оперработника из работы), `weekly_sog_heat` (каждую ночь до конца операции). Решение лежит в почте;
пока оно не принято, неделю не закрыть докладом.

## Третья фаза: главная цель, пробный пакет, «слепое окно»

- **Задача фазы** (`campaign.json → goal`): кроме `recruit_any_of` и `settle_promise` можно
  потребовать сведения — `clues_all: ["clue_caldwell_list"]` («Список»).
- **Перевод Центра** — `fund_usd` у фазы: деньги приходят в первое утро фазы. Валидатор
  сверяет обещанное агенту со стартовым фондом плюс переводами.
- **`days_per_week`** — сколько дней в одном ходе (для четвёртой фазы, где ход — две недели).
- **Пробный пакет** — блок `package` у фазы: `agent`, `title`, `text`, `drop_op` (тайник),
  `handover_op` (личная передача; должна требовать флаг `package_rejected`), `archive_agent`
  (кто сверит с картотекой), `request_id` (запрос с `"package_check": true`) и `mistake_flags` —
  ошибки подхода, при которых пакет из тайника окажется подставой. Подстава определяется
  заранее и видимым игроку правилом; три канала проверки показывают «чисто» или «расхождение».
- **Условия выхода**: `requires_recruited` (агенты), `requires_flags`, `requires_decisions`.
  `essential: true` — ключевое мероприятие: после отмены его можно повторить, поэтому
  валидатор не ищет обходной путь на случай его «срыва».
- **«Слепое окно»** — `sdr.blind_window: true`: если завербован и лоялен агент с perk
  `sog_schedule` (Хэйлс), хвоста на этом выходе нет, а на карте написано почему.
- **Встреча по выходу** — у беседы `requires_op`: встречу назначают выходом на карте
  (например, «Ужин в Джорджтауне»), и только после него можно начать разговор.
- **Перевод «наследства»** — perk `legend` у кандидата (Мендоса): в журнале появляется
  третий способ выплаты без формы 4789, образ жизни растёт вдвое медленнее.
- **Решения** могут менять лояльность агента: `effects.loyalty` и `effects.loyalty_target`.

## Четвёртая фаза: «Окно арестов» (`list/`, `arrest_window`)

- **Дела «Списка»** — `content/list/cards.json`: `card_id`, `name`, `role`, `agency`
  (gru, kgb, research, mfa, defence, other), `damage` (critical, high, medium), `howard`
  (о деле знал перебежчик — арест почти не тревожит Лэнгли), `natural` (как обосновать
  «естественный провал»: seventh, spy_dust, srac или "" — никак), `game` (годится для
  оперативной игры), `dangle` (дезинформация ЦРУ, если пробный пакет принят подставой), `text`.
- **Окно** — у фазы `arrest_window`: `from`, `to` (недели) и `quotas` — квоты Центра
  нарастающим итогом: `by_week`, `arrests`, `damage` ("" — все дела, critical — только
  критические), `text`. Валидатор проверяет, что квоту можно выполнить даже без подделок.
- **Числа** — `balance.json → list`: тревога в Лэнгли за арест с «Ховардом», без него и с
  естественным провалом, порог каскада (`cascade_after`) и его цена, оперативная игра,
  квоты, оспаривание, «Анлейс», подделки, траты агента и «притормозить».
- **Задача фазы** — `goal.flags_all: ["arrest_window_closed"]`: окно закрывается само в
  последнюю неделю графика.
- **Траты агента** — `finance.spending_per_week` у цели: образ жизни растёт без выплат.

## Полиграф ЦРУ (`polygraph/`)

- **Когда и кого**: `act`, `week` (неделя проверки), `subject` (кого проверяют),
  `source_agent` (агент в Управлении безопасности ЦРУ: с ним вызов приходит за
  `notice.weeks_with_source` недель и виден профиль экзаменатора).
- **Подготовка**: `notice.prep_slots_with_source` / `prep_slots_without` — сколько пунктов
  инструктажа успеть; `prep_options` — пункты: `kind` (sleep, sedatives, strategy, legend),
  `stability` (снижает пики на значимых вопросах), `rapport`, `skepticism`; у стратегии —
  `archetype` (под какого экзаменатора она подходит). Легенда снимает `finance_stress` с
  финансового вопроса (скромный образ жизни агента — тоже).
- **Вопросы**: `neutral`, `control_comparison` (ответы задают `control_peak`),
  `relevant_critical` (`base_peak`, `finance`, `pass_formula`). У ответов — `effects`
  (`rapport`, `skepticism`, `control_peak`, `relevant_peak`) и `requires_prep`.
- **Пик**: если реакция на значимый вопрос выше контрольного пика, игрок выбирает объяснение
  из `rationalizations`.
- **Итог** — `outcomes.pass/inconclusive/fail`: тревога в Лэнгли и текст. Валидатор проверяет,
  что проверку можно пройти с полной подготовкой, и предупреждает, если без подготовки — нельзя.

## Концовки и балансный прогон

- **Пороги** — `balance.json → endings`: `triumph_realized` (сколько дел «Списка» реализовать),
  `triumph_mole_hunt_below`, `control_below` (наружка и финансовый след), `double_bottom_trust_below`.
- **Эпилог концовки** — запись архива в разделе `epilogue` с `unlock: "ending:<концовка>"`
  (clean_triumph, pyrrhic_victory, shadow_exchange, double_bottom); `ending:campaign_complete` —
  лист для любой из четырёх (хроника дела Эймса).
- **Проверить баланс после правок**: `tools/balance.sh` — автоигрок проходит всю кампанию тремя
  стратегиями и печатает концовку, недели фаз, риски и итоги «Списка» и полиграфа.

## Объём текста

- Валидатор при каждой проверке печатает, сколько в игре слов; `tools/validate.sh --words` —
  подробно по разделам (документы, улики, беседы, архив, интерфейс…) и по веткам решений.
- `balance.json → text_budget`: `max_words` — потолок (больше — ошибка), `target_min_words` —
  целевой минимум (только в отчёте), `branch_share_max` — какую долю текста может открывать
  один вариант решения (больше — предупреждение «ветка слишком толстая»).
- **Бриллиантовое ветвление**: варианты решения расходятся ненадолго и сходятся. Валидатор
  проверяет, что при любом варианте задачи следующих фаз достижимы — иначе ошибка «Ветка не сходится».

## Письма из дома и «Архив 1985»

**Письмо** — обычный документ почты с `"kind": "letter"`: рисуется тетрадным листом синей ручкой.
`sender` — подпись («Москва, Наташа»), неделя — когда придёт.

**Запись архива** (`archive/*.json`):

```json
{ "id": "arc_fialka", "section": "technique", "status": "fact",
  "title": { "ru": "Шифровальная машина М-125 «Фиалка»" }, "text": { "ru": "…" }, "unlock": "" }
```

- `section`: `history` (история), `technique` (техника и ремесло), `law` (законы США), `fiction`
  (факт и вымысел), `epilogue` (документальный эпилог — листы хроники после финала); `status`: `fact`, `fiction` или `mixed` — на записи ставится штамп.
- `unlock` — событие, после которого запись открывается (например, `act_completed` — после конца
  первой фазы операции) или `ending:<концовка>` — запись открывается в этом финале (эпилог дела
  Эймса — `ending:campaign_complete`); пусто — открыта сразу. Листы эпилога идут в порядке файла. Пишите только то, в чём уверены: это справка, её
  читают эксперты грантов. Реальные люди — только здесь, в исторической справке.

## Возраст 16+

Валидатор проверяет каждый текст (правило «возраст 16+»): мат — ошибка, табак, курение и
употребление алкоголя — предупреждение. Подробнее — `docs/grants.md`, раздел «Правила контента 16+».

## Баланс (`balance.json`)

Все шкалы — от 0 до 100. «Дельта» — на сколько шкала меняется за событие: плюс — растёт,
минус — падает. Шкала, дошедшая до 100, заканчивает кампанию:

- **Наружка ФБР** (`sog_heat`) → высылка резидента (persona non grata);
- **Давление Центра** (`moscow_pressure`) → отзыв в Москву;
- **Охота в Лэнгли** (`mole_hunt`) → арест «крота»;
- **Финансовый след** (`treasury`) → финансовый аудит, после которого охота в Лэнгли ускоряется.

Что за что отвечает:

- `start` — стартовые значения шкал, доверия Центра и спецфонда. `seed` — зерно случайности:
  с одним зерном одинаковые решения дают одинаковый результат.
- `sog_heat` — пропущенный хвост, выезд за 25 миль, повторный выход на ту же точку, оперативная
  пауза (неделя без выходов, обычно минус), проваленный вербовочный подход.
- `moscow_pressure` — сколько недель Центр ждёт спокойно, рост давления без результата и после
  конца акта, награда за выполненную цель акта, реакция на доклады.
- `centre_trust` — как доклады («правда», «приукрасить», «умолчать») меняют доверие Центра.
- `lies` — раз в сколько недель Центр сверяет донесения и с какой вероятностью вскрывает ложь.
- `finance` — банковский контроль и выплаты: порог отчёта 4789 (`ctr_threshold_usd`) и его
  след (`ctr_treasury`), след дробления после закона (`structuring_treasury`, дата закона
  `mlca_date`), оперативные расходы на выезд (`op_expense_usd`), сколько частей можно сделать
  (`max_parts`), образ жизни (`lifestyle_factor`, `lifestyle_decay`, `lifestyle_danger_treasury`),
  лояльность (`loyalty_unpaid_week`, `loyalty_promise_cash`, `loyalty_promise_escrow`,
  `loyalty_per_1000_extra`) и её пороги (`escrow_min_loyalty`, `reports_min_loyalty`).
- Принуждение: `meeting.coercion_threshold` — сколько ответов нажимом и предъявлений компромата
  делают агента неустойчивым; `finance.coerced_loyalty_penalty` — насколько ниже его стартовая
  лояльность, `finance.loyalty_coerced_week` — на сколько она падает каждую неделю. На нуле
  лояльности любой агент рвёт связь.
- `meeting` — `anxiety_cooldown`: на сколько спадает Тревога собеседника к следующей встрече,
  если резидент прервал контакт.
- `cipher` — сверка директив: сколько наружки добавляет исполненная подложная директива
  (`accept_forged_sog_heat`) и какой флаг она ставит, как Центр реагирует на лишний запрос
  подтверждения подлинной директивы (`query_genuine_trust`, `query_genuine_pressure`) и на
  раскрытый подлог (`query_forged_trust`).

Проверить, как правка баланса сказалась на игре, проще всего тестами: `tools/test.sh`. Тест
`tests/test_campaign.gd` проходит три недели разными стилями игры. Если числа поменялись, тест
покажет, где именно, и его ожидания нужно будет обновить (это сделаю я).

## Имена (id)

Только латиница в нижнем регистре, цифры и `_`, с префиксом типа:
`tar_`, `clue_`, `cable_`, `op_`, `exam_`, `req_`, `dlg_`. Например `clue_vargas_drawer_memo`.

## Опечатки в названиях полей

Если в JSON написать поле с опечаткой (например, `"unlok"` вместо `"unlock"`), валидатор покажет
предупреждение «неизвестное поле — опечатка?», а если поле обязательное — ошибку «обязательное поле».

## Демоверсия

`content/campaign.json` → `"demo": {"last_act": 2}` — после какой фазы операции заканчивается
демоверсия (0 — демоверсии нет). Текст экрана «Конец демоверсии» — `ending.demo_complete.text` в
`i18n/ru.json`: если меняешь `last_act`, поправь и его. Сохранение демоверсии полная игра
продолжает со следующей фазы.

## Обучение и памятки

- `content/tutorial/steps.json` — записки заместителя резидента по первой неделе. Поля: `step_id`
  (`tut_…`), `text`, `highlight` (имя предмета на экране, например `desk-object-inbox` или
  `advance-phase` — его обведёт красная рамка), `done` — условие, при котором шаг закроется сам:
  `opened_inbox`, `took_clue`, `verified_directive`, `reached_day`, `planned_op`, `reached_evening`,
  `resolved_op`, `pinned_clue`, `sent_report`, `approved_analysis`, `met_candidate`, `paid_agent` или
  `ack` (кнопка «Понятно»). Шаги идут по порядку файла.
- `content/help/modules.json` — памятки модулей (`view`: map, mice, cipher, finance, dialog,
  counterintel, inbox, archive, evidence): открываются при первом входе в модуль и по кнопке «Памятка».

## Задания Центра

`content/tasks/*.json` — задание приходит в понедельник недели `week` фазы `act`, срок — `due_weeks`
недель (до воскресенья). `requires_recruited` — только если агент завербован; `needs_cables` —
документы, которые надо прочитать перед ответом. Вопросы: `options` с `correct: true` у верного;
у предложений верного нет — у вариантов `effects` (как у решений). `auto: "axis:<цель>"` — мотив
проверяется по досье, `auto: "stability:<цель>"` — устойчивость по шкале лояльности агента.
Числа Доверия и давления — `balance.json` → `tasks`. Задания прошлой фазы снимаются без штрафа.

## Вещественные доказательства (сейф, клавиша 9)

`content/evidence/<id>.json` — предмет приходит в фазу `act` с недели `week` (и после
`requires_flags`). `sides` — стороны (лицо, оборот) с текстом и деталями. У детали `note` —
что видит резидент, когда её осмотрел; у верной (`correct: true`) — `clue_id` (сведения на доску)
и/или `flag_set` (продвигает линию: документы, решения, разговоры по этому флагу).

## Письма домой

У письма семьи (`kind: "letter"`) может быть блок ответа:
`"reply": {"options": [{"option_id": "warm", "label": {"ru": "…"}, "family": 7, "centre_trust": -2}]}`
— варианты ответа и как они меняют «Отношения с семьёй» (0–100) и, если письмо слишком
откровенное, Доверие Центра. Срок ответа, штраф за молчание, порог кризиса и итога —
`balance.json` → `family`. Поле `family` можно добавить и в эффекты решений и разговоров.
